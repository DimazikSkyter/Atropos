# Исправления целостности и развитие рантайма

21.11.2026. Исправления первичного [аудита](INTEGRITY_REPORT.md), метаданные детекторов и первый этап устранения архитектурных ограничений.

## Исправленные ошибки

**INT-01:** `parse_flux` проверяет `pd.isna(timestamp)` до преобразования в наносекунды. Пустая дата, `NaT` и некорректная строка отклоняются. Наносекундная точность и запрет повторных timestamps сохранены.

**INT-02:** общий сервис проверяет правки метрик при `AccountStore.update_metric`, пакетном `import_metrics` и сохранении сетов. Проверяются имя, типы и уникальность лейблов, принадлежность peers, детекторы, неизвестные параметры и допустимость значений через реальные конструкторы. Импорт также проверяет уникальность ID и источник InfluxDB 2.x. Весь пакет валидируется до замены workspace; ошибка не меняет revision и не удаляет сохранённые результаты. Это проверено в отдельной PostgreSQL, включая откат некорректного редактирования.

Реестр и валидатор находятся в `detectors/apps/registry.py`. Импорт научных реализаций ленивый; слой хранения не зависит от Streamlit. UI и хранилище используют один набор реализаций и defaults.

## Метаданные выполненного запуска

В разделе результатов появилась вкладка **«Параметры запуска»**. Она показывает сведения из сохранённого результата:

- ID прогона, revision, начало и завершение, исторический или incremental live-режим;
- класс реализации и SHA-256 файла алгоритма;
- параметры, заданные пользователем, параметры конструктора с defaults и фактические значения после разрешения производных defaults;
- исходную метрику, источник, статус и число готовых точек;
- смысл score, диапазон и явный признак `is_probability: false`.

Для live доступны параметры каждого сохранённого окна, его границы в целых наносекундах, ID сессии и fingerprint конфигурации. Изменение настроек не меняет метаданные старого расчёта. Старые результаты без полного снимка параметров явно помечаются как неполные; текущие defaults не выдаются за исторические настройки.

## Первый этап изменений архитектуры

**Продолжение live-потока.** `DetectorStreams` хранит экземпляр на комбинацию детектор × исходный ряд/пара в пределах сессии. Перекрывающиеся точки не обучают его повторно; новые точки продолжают обучение. Даже если отдельное окно короче прогрева, последующие окна выходят в ready. Отложенные Correlation scores записываются на правильный исходный timestamp, в том числе после выхода целевой точки из текущего окна. Точные пересечения, отсутствие интерполяции и изоляция учёток сохранены. Изменение fingerprint требует новой сессии. Исправленные и запоздавшие точки в сохранённом диапазоне отклоняются с указанием запустить новую сессию; это предотвращает незаметное повторное обучение.

**Ограниченное хранение.** История ограничена временем, числом окон и общим числом исходных/реакционных точек. Кеш перекрытия и число потоков имеют отдельные бюджеты. Перед созданием потока проверяется консервативная оценка размеров его буферов; для SSA учтены матрицы. Бюджет модели измеряется в условных ячейках, а не в байтах RAM. Остановленную завершённую сессию можно удалить вместе с историей. При достижении лимита сессий удаляются только завершённые остановленные сессии; активные вычисления не вытесняются. История показывает число удалённых окон. Replay ограничивает число учёток в очереди/кеше и срок жизни завершённых результатов.

**Ограниченный импорт.** HTTP-ответ читается порциями с проверкой фактического размера после декомпрессии. Парсер ограничивает точки и ряды; replay ограничивает суммарные точки нескольких источников. Превышение возвращает явную ошибку. Частичная обрезанная история не сохраняется как успешный импорт. Режим полной истории `range(start: 0)` сохранён в пределах заданных бюджетов.

**Точное время RuntimeTrend.** UI использует `update_ns(int_timestamp, value)`. Сравнение времени и границы окна выполняются с целыми наносекундами; регрессия использует разности целых timestamps. Соседние наносекунды большого Unix timestamp больше не схлопываются во float. Результат содержит точный `timestamp_ns`; прежний интерфейс `update(seconds, value)` сохранён, смешивание единиц внутри одного экземпляра запрещено.

**Разные шкалы score.** В мониторинге по умолчанию раздельно группируются разные детекторы. Смешанную сумму пользователь включает явно. UI объясняет, что такая сумма — прикладной индекс и может превышать 1. Числовые оценки алгоритмов не изменены; статистическая калибровка не подменена искусственной нормализацией.

**Запуск до браузера.** Уточнение аудита: `make ui` уже вызывал `atropos_ui.serve` и запускал startup-replay до Streamlit. Инструкции приведены к этому штатному способу; порядок `runtime → UI` закреплён тестом. Прямой `streamlit run` остаётся обходным способом с ленивой инициализацией.

## Настройки бюджетов

Все значения — положительные целые числа из окружения процесса. Ошибка настройки приводит к явному отказу.

| Переменная | Default | Что ограничивает |
|---|---:|---|
| `ATROPOS_HTTP_MAX_BYTES` | 67108864 | Один декомпрессированный HTTP-ответ |
| `ATROPOS_IMPORT_MAX_POINTS` | 500000 | Точки одного импорта и суммарные точки источников replay |
| `ATROPOS_IMPORT_MAX_SERIES` | 10000 | Ряды одного ответа Flux |
| `ATROPOS_LIVE_HISTORY_RUNS` | 240 | Сохранённые окна на сессию |
| `ATROPOS_LIVE_HISTORY_POINTS` | 250000 | Исходные точки и все реакции сохранённых окон на сессию |
| `ATROPOS_LIVE_RETENTION_SECONDS` | 86400 | Временной горизонт истории; удаление остановленных сессий старше этого возраста |
| `ATROPOS_LIVE_STREAM_CACHE_POINTS` | 250000 | Общий кеш точек перекрытия и отложенного score на сессию |
| `ATROPOS_LIVE_MAX_STREAMS` | 10000 | Экземпляры детекторов на сессию |
| `ATROPOS_LIVE_MODEL_POINTS` | 2000000 | Оценка суммарных буферов/матриц моделей на сессию |
| `ATROPOS_LIVE_MAX_SESSIONS` | 64 | Сессии процесса |
| `ATROPOS_LIVE_ACCOUNT_SESSIONS` | 16 | Сессии учётки |
| `ATROPOS_REPLAY_MAX_ACCOUNTS` | 64 | Учётки с активным/кешированным replay |
| `ATROPOS_REPLAY_CACHE_SECONDS` | 3600 | Возраст неиспользуемого кеша; очистка при обращениях к рантайму |

По бюджету могут быть удалены исходные точки и реакции старых окон; кеш алгоритма продолжает обучение. После удаления кеша старых точек исправления за пределами сохранённого диапазона не проверяются. В сессии нет автоматического backfill пропущенных во время паузы окон. Для переобучения на изменённой истории нужна новая сессия.

## Следующие архитектурные этапы

Состояние live-моделей и история пока остаются в RAM одного процесса и теряются при перезапуске. Для долговечного и распределённого исполнения нужны checkpoint состояния и согласование владельца сессии между процессами. Отдельный worker/API теперь реализован в [контейнерном backend](CONTAINERS.md). Исторические результаты по-прежнему сохраняются в PostgreSQL только при включённом `persist_results`. Лимиты точек и моделей не являются жёсткой квотой RAM операционной системы. Статистическая калибровка и веса смешанной суммы требуют отдельной предметной модели и размеченных данных.
