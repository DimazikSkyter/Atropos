# Почему результат отличается от тестовой картинки

Ранее использовался один вызов `MADDetector.detect()` на всём ряду Kafka,
с параметрами класса по умолчанию: локальное окно 10, общий MAD по всем 1521 точкам.
Исходный тест задаёт `window=20, data_max_size=100`, затем на каждом шаге передаёт
`metrics.sub_range_metrics(point, point+100)`. После первого вызова сохраняется
только последняя оценка. Таким образом, общий MAD пересчитывается на движущемся
референсе и адаптируется к выросшему разбросу.

В точном повторении последовательности теста на Kafka получено:

| Параметр | Прежний прогон | Как в тесте |
| --- | --- | --- |
| Локальное окно | 10 точек / 2,5 мин | 20 точек / 5 мин |
| Общий MAD | Вся история | Скользящий фрагмент 100, фактически 99 точек |
| Средняя оценка последних 20 минут | 0,7262 | 0,0683 |
| Максимум исходной оценки | 0,95349 | 0,54699 |

Для отделения влияния локального окна также посчитан офлайн-прогон с окном 20:
средний скор последних 20 минут **0,7661**. Следовательно, основное различие
объясняется движущимся референсом, а не только заменой 10 на 20.

В тесте используется другой входной ряд: 1000 гауссовских значений со sigma=0,1,
затем 1000 значений с sigma от 0,1 до 10,09. Kafka содержит заметные колебания
уже в начале и восстановлена по изображению. Совпадение формы двух графиков
не ожидается. Случайный seed теста не задан, поэтому и его повторения различаются.

## Найденная пограничная ошибка

`Metrics._compute_indexes` возвращает индекс последней точки до правой границы,
а `sub_range_metrics` использует этот индекс как исключаемый конец Python-среза.
Из запроса 100 точек получается 99. Точный тестовый цикл на Kafka выдаёт 1520
оценок и заканчивается в 02:19:45, не обрабатывая конечную точку 02:20:00.
Это поведение сохранено для сравнения; исходный репозиторий не изменялся.

`data_max_size=100` сам по себе не задаёт референс: в MADDetector этот атрибут
не используется. Референс определяется переданным в `detect()` фрагментом.
Порог объявления аномалии исходным классом не предусмотрен.

`Metrics.py` в репозитории был изменён после предыдущего прогона:
восстановлен конструктор `Metric`. Формулы MADDetector и методы среза Metrics
не изменились. Для этого запуска сохранены актуальные копии в `source/`,
их SHA-256 — в `report.json`. При создании Metric/Metrics и выполнении цикла
использованы исходные методы без изменения вычислений.

На существующем дашборде Kafka фиолетовая линия показывает прежний режим,
зелёная — сценарий теста. Обе линии сглажены средствами InfluxDB по минутам:
381 точка и 380 точек соответственно. Внизу показаны отдельные пары локального
и общего MAD для каждого режима. Исходные данные и прежние оценки сохранены.

`data/results.csv` — результат на Kafka; `data/metrics.lp` — новый measurement
`kafka_write_mad_test` для воспроизведения в InfluxDB. `report.json` — режим и
численные сравнения, `verification.json` — сверка с InfluxDB/Grafana.

Повторный расчёт: `python -B compare_modes.py` (нужен NumPy).
