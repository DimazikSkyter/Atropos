# Прогон WindowedMadDetector на времени записи в Kafka

Вход — живой ряд InfluxDB `kafka_write_time/value` за 15.09.2026 20:00 —
16.09.2026 02:20 (Москва): 1521 точка с шагом 15 секунд. Данные сверены с исходным
CSV реплея; используется сырой ряд, без скользящего среднего и без изменения значений.

Запущен `MADDetector.detect()` из предоставленного `WindowedMadDetector.py`.
Окно по умолчанию — 10 точек (2,5 минуты). В `Metrics` передан размер 1521,
чтобы контейнер не обрезал историю. `data_max_size=50` оставлен по умолчанию:
этот атрибут не используется в вычислениях данного детектора.
В конфигурации приложения задано другое окно, 5; этот прогон использует значение
по умолчанию именно приложенного класса, без изменения параметров под результат.

Формулы исходного кода:

```text
globalMAD = mean(abs(x - mean(x)))               # вся история
localMAD[t] = mean(abs(window[t] - mean(window[t])))
relative[t] = abs(localMAD[t] - globalMAD) / globalMAD
score[t] = 2 / (1 + exp(-relative[t])) - 1
```

Это **среднее абсолютное отклонение**, а не медианное MAD. Скор — оценка 0–1,
не вероятность. В исходном классе нет порога классификации, поэтому метки
«аномалия / норма» не добавлены. Первые 9 точек — нулевой скор: исходный код
подставляет в них общий MAD. Отклонение разброса в обе стороны увеличивает скор.

Режим — один офлайн-вызов по всей истории. Общий MAD включает поздние значения;
это не проверка потоковой работы без информации о будущем.
Входные данные восстановлены из изображения и интерполированы, поэтому результат
не является оценкой качества детектора на исходных измерениях Kafka.

Среднее ряда: 473,627 мс. Общий MAD: 22,708 мс.
Максимальная оценка: 0,953489 в 02:15:15 16.09.2026, локальный MAD 107,585 мс.
В середине истории средний локальный MAD — 11,881 мс,
в последние 80 минут — 43,971 мс: рост примерно в 3,7 раза.

`source/` содержит неизменённые копии класса, базового Detector и Metrics.
`run_mad.py` компилирует исходные AST-узлы этих классов без правки методов;
это позволяет не загружать Keras и matplotlib, импортируемые модулями,
но не используемые данным вычислением. SHA-256 исходников записаны в `report.json`.
Результаты сверены с независимым арифметическим расчётом для всех 1521 точек.
Исходный репозиторий не изменён.

Файлы: `data/kafka-write-time.csv`, `data/results.csv`, `report.json`.
`data/metrics.lp` — результаты для InfluxDB: measurement `kafka_write_mad`,
tags `mode=offline,window=10`, поля `score`, `local_mad_ms`, `global_mad_ms`,
`relative_deviation`. Точки не заменяют исходный ряд.

На существующем дашборде Kafka добавлены две панели под исходным графиком:
скор детектора и локальный/общий MAD.

Отображение оценки MAD сглажено средствами Flux:
`aggregateWindow(every: 1m, fn: mean, createEmpty: false, timeSrc: "_start")`.
В полном окне усредняются четыре исходных оценки с шагом 15 секунд.
На полном диапазоне получается 381 точка вместо 1521; последняя минута
неполная и содержит только конечный отсчёт. В БД остаются все исходные оценки,
детектор не пересчитывается на усреднённом входе. Локальный/общий MAD и исходный
ряд Kafka сохраняют прежнее отображение. Максимумы сглаженной кривой могут
быть ниже исходного пика 0,953489. Результат проверки — `smoothing-verification.json`.

Повторный запуск требует NumPy и доступа к локальному InfluxDB:

```powershell
python -B run_mad.py
```
