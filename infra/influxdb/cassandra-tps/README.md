# TPS с привязкой к истории Cassandra

[Общий график ВО/TPS](http://localhost:3001/d/cassandra-tps-correlation) добавлен в
[InfluxDB Replay](http://localhost:3001/d/influxdb-replay).

Measurement `cassandra_tps`, поле `value` (TPS), tag `trace`:
`green`, `yellow`, `gray`, `red`, `olive`, `teal`, `orange`.
Легенда на скриншоте обрезана, поэтому серии названы по цветам и не приписаны нодам.
Это приблизительная реконструкция изображения, не реальные измерения нагрузки.
Основные уровни около 700, 485, 130, 84, 61, 30 и 22 TPS.
Слабо различимая бирюзовая линия частично оценена как 30 TPS до падения и 10 после;
перекрывающиеся нижние линии восстановлены менее точно, чем зелёная и жёлтая.

Пользователь подтвердил, что под `cassandra_compaction_response_time` имелся в виду
существующий measurement `cassandra_response_time`. Его точки используются для
привязки времени. История Cassandra не переписывается.

| Событие, 02.10.2026 (Europe/Moscow) | Время | TPS |
| --- | --- | --- |
| Окончательный спад первой ноды | 04:53:30 | Уровень без отдельной реакции |
| Высокое плато ноды 2 | 07:51:30 | Уровень сохраняется |
| Высокое плато обеих нод | 08:41:15 | Частичное падение, нагрузка остаётся |
| Последний высокий участок ноды 3 заканчивается | 12:16:15 | Остаточная нагрузка остаётся |
| Последний высокий участок ноды 2 заканчивается | 12:30:00 | Все TPS = 0 |

До плато обеих нод уровень TPS сохраняет исходные небольшие колебания/дрейф;
событие изменения шума в период роста ВО не добавляется, поскольку оно не подтверждено.
После частичного падения используется видимый шумный остаточный участок картинки.
После 12:30 добавлены явные нули, а не отсутствие данных. Последние 15 минут
нулевого участка позволяют увидеть полную остановку на графике.

Временная ось изображения преобразована кусочно-линейно: исходный участок до
падения → 01.10 21:00–02.10 08:41:15; остаточный участок → 08:41:15–12:30.
Размытый вертикальный соединитель исключён из остаточного участка. Шаг — 15 секунд,
3 781 точка на серию, 26 467 всего; конец — 02.10.2026 12:45:00.

Плато определяется первым значением ≥25 ms, после которого медиана следующих
20 минут ≥25 ms и минимум 80% значений ≥21 ms. Терминальный спад — первая точка
после последнего значения ≥20 ms. Это отметки графика, а не записи журналов отказов.
Точность исходных уровней и субпиксельного времени ограничена размытием скриншота.

Готовые `metrics.lp` импортирует существующий `seed-replays.sh`; повторный импорт
тех же measurement/tag/timestamp не создаёт дубликатов. Загрузка хранится в
существующем постоянном volume InfluxDB, срок хранения bucket — один год.

```powershell
python infra/influxdb/cassandra-tps/generate.py
python infra/influxdb/cassandra-tps/build_dashboard.py
python infra/influxdb/build_overview.py
docker compose -f infra/docker-compose-monitoring.yml run --rm influxdb-seed
```

`generate.py` использует стандартную библиотеку; исходник — `reference-traces.csv`.
Повторная оцифровка (`digitize_reference.py`) и статический `preview.png`
(`plot_preview.py`) требуют numpy, Pillow и matplotlib.
