# Проверка experiment3 — 3 октября 2026 (Москва)

Проверен сценарий **от старта до OOM**: 750 RPS, пять минут baseline 30–40 ms,
затем 40–60 ms, timeout 50 ms, два retry через 1 и 2 секунды, 48 клиентских слотов.

Два JVM прогона подтвердили настоящий `java.lang.OutOfMemoryError: Java heap space`:
406,0 и 416,85 s от запуска нагрузки. Сервис 2 сохранил работоспособность.
Сервис 1 использует Java 21 / Parallel GC, `-Xmx128m`, контейнер 256 MiB.
Это JVM heap OOM с exit code 3, а не Docker cgroup kill.

Последний прогон: [проверка](results/20261002T212722Z/verification.json),
[Grafana](http://localhost:3001/d/experiment3-retry-oom?from=1790976442098&to=1790976873946).

- OOM на 6 min 56,85 s, после пятиминутной стабильной фазы и до 600 s.
- На стабильном участке после 60 s прогрева: максимум очереди 2,
  169 timeout из 168599 входящих запросов (~0,10%).
- Максимальная записанная очередь — 25614 запросов с уникальными payload 4 KiB.
- До OOM k6 не пропустил итераций; назначенный поток — постоянные 750 RPS.
- GC log содержит 1218 minor / Pause Young и 746 major / Pause Full.
  Графики последних сборок сохраняются после OOM благодаря экспорту лога сервисом 2.
- Все 12 проверок требуемого интервала в verification.json прошли.

Запись последнего прогона продолжалась до десяти минут: после OOM генератор
получал ошибки обращений к остановленному контейнеру и пропускал итерации.
Эти данные сохранены отдельно от проверки живого эксперимента:
`verification-initial.json`, поля `*_in_full_recording` и k6 summary.
Финальный runner **останавливает нагрузку при подтверждённом OOM**;
десять минут используются как предельное время ожидания падения.
Сырые ряды проверки нагрузки до OOM: `load-until-oom.json`.

Сборка включает Go tests / go vet и Java HTTP tests: admission, payload retention,
late callback correlation, delay queue ordering и наличие minor/major GC metrics.
Проверены Compose config, подключение двух targets VictoriaMetrics и 16 панелей Grafana.
Исторические калибровочные прогоны сохранены, результаты исключены из Git.

После проверки сервис 1 оставлен в состоянии OOM, сервис 2 и общий мониторинг работают.
Повторный запуск: `python infra/experiment3/run.py run`; он пересоздаёт оба сервиса.
`up` также пересоздаёт сервисы, сбрасывая фазу деградации. Общие данные мониторинга
не удаляются. Графана открыта на интервале последнего эксперимента.
