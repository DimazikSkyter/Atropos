# Скользящие ACF/PACF и поиск циклов

Команды из `Atropos/detectors`:

```powershell
uv sync --locked
uv run python -m unittest tests.test_correlation -v
uv run python -m tests.visualize_correlation --output artifacts/correlation
```

Зависимости добавлены в `pyproject.toml` и `uv.lock`: NumPy, pandas, SciPy,
statsmodels; Matplotlib из `dev` строит графики без GUI.

```python
from apps.correlation import RollingCorrelationAnalyzer
from apps.generator import CycleConfig, TimeSeriesGenerator

metric = TimeSeriesGenerator(
    mean=100, cycles=(CycleConfig(10, 3), CycleConfig(100, 5)), seed=44,
).generate(200)
result = RollingCorrelationAnalyzer(window=20).analyze(metric)

print(result.window)                 # 25 при обнаружении периода 100
print(result.timestamps)             # timestamps первых точек каждого окна
print(result.values['acf'])          # DataFrame: окна × лаги 0..7
print(result.values['pacf'])         # DataFrame: окна × лаги 0..7
print(result.values.attrs)           # periods, step, max_lag, методы и др.
```

## Правила расчёта

Поиск циклов выполняется один раз по всему временному ряду. После этого:

```text
window = max(input_window, floor(max_period / 4), 4 * explicit_max_lag)
step = floor(window / 2)
max_lag = explicit_max_lag, если задан; иначе ceil(window / 4)
```

Если max_lag не передан, член `4 * explicit_max_lag` равен нулю; вычисление
автоматического лага после выбора окна не расширяет окно повторно. При отсутствии
циклов член max_period равен нулю. Параметры выражены в **точках**, не секундах.
`window` должен быть целым >= 4, явно заданный `max_lag` — целым >= 1.

Сегменты `[start, start + window)` полные, с исключённой правой границей.
Начало сдвигается на step, неполный хвост отбрасывается. ACF/PACF вычисляются
по полному выбранному сегменту; половина окна относится к шагу перемещения.
При нечётном окне шаг округляется вниз. Если ряд короче выбранного окна,
возвращается пустой DataFrame с корректными колонками, окном и метаданными.

| Вход | Периоды | Окно | Шаг | Лаги |
|---|---|---|---|---|
| 1000 точек, window=50 | Нет | 50 | 25 | 0..13 |
| window=50 | 365 | 91 | 45 | 0..23 |
| window=50 | 10 | 50 | 25 | 0..13 |
| 200 точек, window=20 | Нет | 20 | 10 | 0..5 |
| 200 точек, window=20 | 10 и 100 | 25 | 12 | 0..7 |
| window=20, max_lag=8 | Нет | 32 | 16 | 0..8 |

В первом примере получается 39 строк: 0–50, 25–75, …, 950–1000. В примере
200 точек/окно 20 — 19 строк: 0–20, 10–30, …, 180–200. При периоде 100
получается 15 окон: 0–25, 12–37, …, 168–193; оставшиеся 7 точек не образуют
полного очередного окна.

## Структура результата

`apps.metrics.DataframeResult` хранит:

- `name`, `tags` — имя и копия тегов исходной метрики;
- `values: pandas.DataFrame` — строка на окно, MultiIndex колонки `(function, lag)`;
- `timestamps: list[int]` — Unix seconds начала каждого окна;
- `window: int` — фактически выбранное окно в точках.

Индекс DataFrame совпадает с `timestamps` и называется `timestamp`.
`values.attrs` содержит `input_window`, `step`, `max_lag`, `periods`,
`constant_windows`, `acf_method`, `pacf_method`. Входной MetricResult не меняется.
Настройка `analyzer.window` хранит входящее окно; фактическое находится в
`result.window`, поэтому один анализатор можно переиспользовать для разных рядов.

ACF — смещённая нормированная оценка (adjusted=False), вычисляемая через FFT.
PACF — оценка Бёрга. Лаг 0 включён и равен 1 у невырожденных окон. В постоянном
окне дисперсия нулевая, поэтому все коэффициенты обозначаются NaN. Интервалы
доверия и p-value в этой версии не вычисляются. Поддерживаются равномерные
timestamps; нерегулярный ряд нужно сначала привести к равномерной сетке.

API и методы: [ACF statsmodels](https://www.statsmodels.org/stable/generated/statsmodels.tsa.stattools.acf.html),
[PACF Burg statsmodels](https://www.statsmodels.org/stable/generated/statsmodels.tsa.stattools.pacf_burg.html).

## Выбор функции цикличности

По умолчанию `fft_periods` выделяет пики FFT после оконной функции Hann,
уточняет период синусоидальной регрессией и округляет до ближайшего целого.
Принимаются до 3 периодов, каждый должен объяснять не менее 20% дисперсии
исходного ряда и повторяться хотя бы два раза. Это эвристика для выраженных
циклов; слабые циклы могут быть пропущены, а случайные колебания — приняты за
цикл. Она не использует параметры генератора и не гарантирует отсутствие
ошибок на произвольном шуме. Максимальный обнаруживаемый период при настройках
по умолчанию — половина длины всего ряда.

Функцию можно выбрать или параметризовать:

```python
from functools import partial
from apps.correlation import fft_periods, RollingCorrelationAnalyzer

analyzer = RollingCorrelationAnalyzer(
    window=20,
    cycle_function=partial(fft_periods, min_power_fraction=0.1, max_cycles=3),
)

# Произвольная функция получает независимый NumPy-массив значений и возвращает
# последовательность периодов в точках. Пустая последовательность = нет циклов.
def known_periods(values):
    return (365,)

analyzer = RollingCorrelationAnalyzer(window=50, cycle_function=known_periods)
```

## Визуализация и проверки

Все восемь рядов имеют 200 точек, входящее окно анализа — 20.
Ось Y графиков временных рядов начинается с 0. Карты ACF/PACF показывают
только лаги `1..max_lag`: нулевой лаг исключён из визуализации.
В DataframeResult и CSV сохраняются все рассчитанные лаги, включая нулевой.

`report.png` содержит шесть базовых вариантов и их карты ACF/PACF: белый шум,
смешанный стационарный шум без циклов, цикл 10, циклы 10 и 100, а также два
дополнительных варианта с большим шумом — без циклов и с периодом 10.
В последних двух Gaussian/AR(1)/Student-t компоненты усилены в 10 раз:
std_percent=3.5/4/1, AR(1) correlation=0.65, Student-t df=5. Сохраняется возможность
редких фоновых всплесков с настройками генератора по умолчанию. Период 10 имеет
амплитуду 5% от mean=100, поэтому шум сопоставим с величиной цикла.

`anomalies.png` содержит отдельно два варианта стационарной базы из
`TimeSeriesGenerator` (seed=47, mean=100, одинаковые случайные инновации):

- Точки `[0, 100)` остаются исходными, с точки 100 до 199 добавляется линейный
  тренд: `value[i] = original[i] + (i - 100) * tan(radians(10))`. Это угол 10°
  в координатах «индекс точки — единица значения»; slope ≈ 0.176327 единицы
  на точку, ≈ 0.705308 единицы в минуту при шаге 15 секунд. Первое значение
  трендового участка сохраняет непрерывность, последняя добавка ≈ 17.456371.
  Геометрический угол на изображении зависит от масштаба осей.
  **Дисперсия шума удвоена** на всём ряду: std_percent каждого из трёх шумовых
  компонентов умножен на sqrt(2), корреляция AR(1) и df Student-t сохранены.
  Речь об остаточном шуме после удаления заданного тренда; сам тренд также
  вносит вклад в общую дисперсию ряда. Наклон и средний базовый уровень сохранены.
- Точки `[100, 115)` увеличены на 20% относительно исходных значений (`value * 1.2`);
  с точки 115 серия полностью возвращается к исходной базе. Изменены ровно
  15 точек. Исходный ряд сохраняется отдельно.
  Этот вариант использует прежние параметры шума по умолчанию.

Оба варианта используют `AnomalyGenerator`. На графиках синий — оригинал,
оранжевый — аномальный участок; карты ACF/PACF рассчитаны для ряда с аномалией.
Поиск циклов остаётся общей FFT-эвристикой: случайный шум, тренд или всплеск могут
повлиять на найденные периоды; обнаруженные периоды выводятся фактически,
параметры генератора не подставляются в анализатор.

CSV `*-series.csv` сохраняют все восемь рядов, `*-correlations.csv` — коэффициенты,
`*-original.csv` — исходные стационарные ряды двух аномальных вариантов.
`summary.json` содержит обе группы, параметры шума, seed, параметры аномалий,
реальные обнаруженные периоды, окно, шаг, лаги и границы.

Тесты проверяют эти сценарии, все три исходных примера, явный max_lag, выбранный
callback, прямую формулу ACF и первый коэффициент PACF, сравнение с библиотекой,
копирование данных, JSON-логи, короткий ряд, постоянные окна и неполный хвост.
Дополнительные проверки подтверждают интенсивность шума, точный наклон тренда,
двукратную дисперсию остаточного шума, увеличение ровно 15 точек на 20%, восстановление
оригинала и экспорт обеих визуализаций.

## Изменение связи между несколькими рядами

`apps.detectors.CorrelationDetector` оценивает изменение связи онлайн,
без ручного выбора нормальных участков. Текущая CCF сравнивается с медленным
эталоном по предшествующим взаимодействиям; сильное нарушение блокирует
обучение этой пары. С пятой точки скор выдаётся непрерывно, включая рост окна.
API, полные графики и live-тесты InfluxDB за 18.10.2026 —
[CORRELATION_CHANGE.md](CORRELATION_CHANGE.md).

Корреляционный скор учитывает относительное расхождение на текущем уровне
(`relative_change_scale=0.1`) и настраиваемый допуск времени сбора
(`alignment_tolerance=1` для ±1 отсчёта). Допуск добавляет задержку выдачи;
результат различает индекс оцениваемой точки и индекс выдачи. Подробности и
сравнение на исходных рядах — в [CORRELATION_CHANGE.md](CORRELATION_CHANGE.md).
