# CUSUM: аномальные падения, возвраты и адаптация фона

## Обновление 22 ноября 2026

Основной сценарий интерфейса использует `drift_mode='adaptive'`: CUSUM оценивает
необычные падения с возвратами относительно предыдущей истории, а не наличие пилы
само по себе. Допуск равен `drift_std_fraction * sigma` предыдущих дельт;
по умолчанию `drift_std_fraction=0.5`, то есть 50% фонового стандартного отклонения.
95-й процентиль ограничивает редкие края только при оценке sigma. Использовать
сам этот процентиль как порог каждого движения было слишком агрессивно: на
трёхчасовом CPU отклик подавлялся до 0.0033. Теперь привычные циклы могут давать
слабый ненулевой отклик, а нерегулярные всплески — более заметный.
Текущее окно не обучает свой фон. Затем прошедшие изменения входят в скользящий
фон: повторяющийся новый режим становится обычным. Редкие крайние разности
ограничиваются тем же процентилем только при оценке фоновой sigma; исходный ряд
не сглаживается и не изменяется. Это внутренний расчёт CUSUM, не детектор MAD.

Оба накопителя и относительная инерция сохранены. Обученная нормальная пила
перестаёт подпитывать реакцию; конечная линейно затухающая память реакции
ограничена `inertia_window`. Поэтому на появлении пилы реакция растёт, затем
постепенно падает при привыкании. Большая пила поверх обычной малой даёт новую
существенную реакцию. `threshold=5` сохранён; это масштаб нормированного
накопленного свидетельства, а не число в единицах исходной метрики.

```python
detector = CusumDetector(drift_mode='adaptive', drift_quantile=0.95,
                         drift_std_fraction=0.5,
                         threshold=5, window=10, reference_window=100,
                         inertia_window=200)
```

Для воспроизводимости сохранённых старых прогонов конструктор без `drift_mode`
оставляет прежний режим `sigma`; новые привязки CUSUM в интерфейсе явно сохраняют
`adaptive`. Данные и параметры старых результатов не переписываются задним числом.

Обновлённый [основной отчёт](artifacts/cusum/report.html) сравнивает оба режима,
содержит CPU с шагами 15 и 30 секунд, трёхчасовой CPU с шагом 15 секунд
и отдельный опыт с малой и большой пилой.
Сборка: `python -m tests.visualize_cusum_adaptive --output artifacts/cusum`.

## Совместимый режим sigma: описание предыдущей версии

Обновление от 11 ноября: четыре исправленных TPS-ряда «Сценария»
за 17–18 октября и четыре ряда Cassandra из InfluxDB находятся в конце [отчёта](artifacts/cusum/report.html#latest-inputs).

`apps.detectors.CusumDetector` оценивает берст или пилу в текущем окне с памятью
инерции. Балл `[0, 1]` учитывает фоновый шум, глубину относительно уровня ряда
и количество накопленного движения. Короткая неглубокая просадка получает
низкий балл, повторяющиеся просадки постепенно набирают высокий.
Горизонтальная прямая даёт ровно `0`. Односторонние смены уровня и монотонный
тренд оценивают другие детекторы.

```python
from apps.detectors import CusumDetector

# Один экземпляр на ряд. Оба окна задаются в точках, не секундах.
detector = CusumDetector(window=10, inertia_window=200)
for value in metric.values:
    score = detector.update(value)
    if detector.ready and score >= 0.5:
        print('Burst/saw in the current window:', score)

# Для графиков: независимый причинный прогон всей истории.
scores = CusumDetector().detect_single_seria(metric.values)

# Отдельный фрагмент с явно заданным спокойным фоном.
score = CusumDetector(window=10).fit(healthy_values).score(fragment_values)
# detect(values) — синоним score(values).
```

Для накопления инерции между вызовами нужен `update()`. Пакетный `score()`
оценивает только переданный фрагмент как независимый прогон, поэтому короткое
окно не расскажет ему о сотне предыдущих просадок. Для пакетного анализа
повторяющейся пилы передавайте её историю целиком в `detect_single_seria()`
или `score()`. Итоговый балл относится к последнему окну этой истории.

## Расчёт

1. Первая разность `d[i] = x[i] - x[i-1]`. Первая точка разности не образует.
2. Фоновый масштаб `sigma = max(noise_floor, std(background_deltas))`,
   стандартное отклонение с делителем N. Оценка исключает разности текущего
   окна, чтобы сам дефект не поднимал свой шумовой порог. Для независимого
   стационарного шума `Var(d) = 2 Var(x)`; при корреляции равенство не действует.
3. В последних `window` значениях вычисляются `window - 1` разностей и два
   CUSUM: `C+ = max(0, C+ + d/sigma - drift)` и
   `C- = max(0, C- - d/sigma - drift)`.
   Разность через левую границу окна не входит в оценку. Среднее фоновой
   разности не вычитается. Из максимумов накопителей `P` и `N` получается
   шумовой балл `Q = 1 - exp(-P*N / threshold**2)`.
4. Уровень `L` — медиана последних `min_reference_samples` принятых фоновых
   значений. Разности текущего окна и их значения в этот фон не входят.
   Масштаб уровня `A = max(abs(L), sigma)`; запас по sigma делает определение
   устойчивым около нулевого уровня, где проценты от среднего не определены.
5. Каждое движение даёт вклад
   `m = max(0, abs(d) - max(sigma, relative_drift*A)) / A`.
   Учитывается только движение сверх фонового шума и небольшого допуска
   относительно уровня. Здесь вычитается один sigma: более строгую проверку
   `drift*sigma` уже делает CUSUM. Это сохраняет постепенную часть восстановления.
6. Положительные и отрицательные вклады суммируются отдельно в последних
   `inertia_window` разностях: `U` и `D`. Балл инерции
   `I = 1 - exp(-U*D / relative_threshold**2)`.
7. Итог: `score = Q*I`. Если окно не содержит обоих существенных направлений,
   `Q=0` и итог равен нулю, независимо от прошлой инерции. Когда в целом окне
   оба CUSUM равны нулю, память инерции очищается. Новая небольшая просадка
   после спокойного участка не наследует силу прошлого берста.

Для численной устойчивости нормированные величины ограничиваются сверху
`1e6`: такие движения уже насыщают соответствующий балл. Множитель двух
направлений сохранён в обоих компонентах. Много небольших движений может
набрать столько же инерции, сколько несколько глубоких; редкая неглубокая
просадка этого не делает. Нет общего ограничения «все небольшие движения
не выше 0.2»: именно их повторение должно постепенно оцениваться сильнее.

Сброса при достижении порога нет: продолжающаяся пила должна оставаться
видимой. Нормировка min-max всего ряда и рекурсивное сглаживание исходного
детектора заменены причинной оценкой шума, относительного уровня и инерции.

## Параметры и фон

| Параметр | По умолчанию | Смысл |
|---|---:|---|
| `window` | 10 | Точек текущего окна; минимум 3; оно должно вместить оба направления |
| `inertia_window` | `20*window` | Максимум разностей для накопления движения; минимум `window` |
| `threshold` | 5 | Масштаб `sqrt(P*N)` в шумовом балле Q |
| `drift` | 3 | Допуск на шум для каждого CUSUM, в sigma |
| `relative_threshold` | 0.5 | Масштаб `sqrt(U*D)` в балле инерции I; увеличение снижает балл |
| `relative_drift` | 0.01 | Допуск в каждом вкладе инерции: 1% от масштаба уровня |
| `reference_window` | 100 | Максимум принятых фоновых разностей и соответствующих уровней |
| `min_reference_samples` | 20 | Минимум разностей для фона; также число последних уровней для медианы |
| `noise_floor` | 1e-9 | Минимальный sigma в единицах метрики |
| `update_sigma` | 8 | Разности выше этого модуля в sigma не обучают фон |

Без `fit()` первые `min_reference_samples + 1` точек учат фон; следующие
`window - 1` разностей заполняют окно. При настройках по умолчанию первая
готовая оценка появляется на 30-й точке. До готовности `ready=False`, балл 0.
Первый участок предполагается нормальным. `fit()` требует минимум
`min_reference_samples + 1` здоровых значений, учит шум и уровень и очищает
предыдущий поток. Между его концом и первым значением фрагмента разность
не образуется.

Значения текущего окна отложены до выхода из него. Окна с шумовым баллом
`Q>=0.5` исключаются из обучения фона, даже если итоговый `score` пока низок
из-за малой глубины или длительности. Иначе фон быстро привыкал бы к пиле
до набора инерции. Отдельные разности выше `update_sigma` также исключаются.
Для принятия нового нормального шумового режима следует явно вызвать
`fit(new_healthy_values)`; автоматически отличить его от длительного дефекта
не всегда возможно.

`reset()` очищает поток, окно и инерцию, сохраняя явный фон из `fit()`.
`detect_single_seria()`, `detect()` и `score()` не меняют активный поток:
используются настройки и явный фон из `fit()`, без его текущей инерции.
Принятые спокойные значения могут адаптировать фон после `fit()`.
`noise_std` показывает шум разностей, `background_level` — фоновый уровень.

## Границы применения

Балл — эвристическая выраженность дефекта, не калиброванная вероятность.
Глубина, частота и повторение совместно влияют на него. Требование <=0.2
закреплено для исходного короткого неглубокого теста и похожих fixtures,
а не для произвольного ряда. Длинная пила небольшого размаха должна набирать
больший балл. Это также меняет время реакции относительно прежней версии:
мелкая пила сначала оценивается слабо, а затем усиливается.

Окно должно включать оба направления события. При просадке длиннее окна
границы могут не встретиться: чистый низкий уровень без колебаний не является
берстом для этого детектора. Сильная корреляция и нерегулярный scrape меняют
масштаб разностей. Используется порядок точек, не timestamps; пропуски не
интерполируются. Counters сначала следует преобразовать в rate с reset.

Память ограничена `O(reference_window + window + inertia_window)`.
Обновление пересчитывает sigma, медиану уровня, CUSUM и суммы инерции:
`O(reference_window + min_reference_samples*log(min_reference_samples) + window + inertia_window)`.
Параметры имеют другие единицы, чем старые min-max `threshold=1, drift=0.01`.
Интеграция с источниками, алертами и UI в обязанности класса не входит.
