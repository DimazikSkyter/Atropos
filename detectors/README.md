# Runtime trend detector

Детектор устойчивой **смены** тренда с накоплением score 0…1, оценкой начала
излома и горизонтальности ±1°: [TREND_CHANGE.md](TREND_CHANGE.md).
Масштабный отчёт: [artifacts/trend-change/report.html](artifacts/trend-change/report.html).

Модуль запускается через **uv**, Python >= 3.12. Генератор использует NumPy;
визуализация тестовых сценариев — Matplotlib из группы `dev`.
Все команды ниже выполняются из `C:\Users\dimaz\IdeaProjects\Atropos\detectors`.

```powershell
uv run python -m unittest discover -s tests -t . -v
uv run python -m apps.demo --output artifacts/runtime-trend
uv run python -m unittest tests.test_generator -v
uv run python -m tests.visualize_generator --output artifacts/generator
uv run python -m unittest tests.test_correlation -v
uv run python -m tests.visualize_correlation --output artifacts/correlation
```

Демонстрация создаёт подробный `report.html` по 28 сценариям: 12 исходных и
16 рядов из тестов Bond/PredictionIntervalDetector. На графиках показаны ряд,
наклон и его пороги, остаточный момент и причины решений; каждое выбранное окно
разобрано отдельно. Включены PNG, поточечные CSV, сводки JSON/CSV и задержки
для размеченных трендов. Красные отметки — рост, голубые — падение.
Это моменты проверки детектора. Формат, результаты и воспроизведение:
[RUNTIME_TREND_REPORT.md](RUNTIME_TREND_REPORT.md).

## Использование

```python
from apps.runtime_trend import RuntimeTrendDetector, TrendConfig

detector = RuntimeTrendDetector(TrendConfig(
    window_seconds=120,
    variance_threshold=1.0,
    min_tangent=1.0,
    value_scale=1.0,
))

# Реальный поток: timestamp в секундах, value — значение gauge.
for i in range(81):
    detector.update(timestamp=i * 15.0, value=20.0 + i * 0.5)
    if i % 4 == 0:  # оценка раз в минуту при scrape 15 секунд
        result = detector.evaluate()
        if result.detected:
            print(result.direction, result.tangent, result.residual_variance)
```

Один экземпляр хранит состояние одного ряда. Он не потокобезопасен.

## Семантика параметров

| Параметр | Значение |
|---|---|
| `window_seconds` | Длительность скользящего окна по timestamp, не число точек |
| `variance_threshold` | Максимальный робастный остаточный второй момент после удаления линии, в квадрате нормализованных единиц |
| `min_tangent` | Минимальный модуль наклона: `(value / value_scale) / минута`; сравнение строгое `>` |
| `value_scale` | Масштаб оси значений; по умолчанию 1 |
| `min_samples` | Минимум наблюдений, по умолчанию 8 |
| `min_coverage` | Минимальная доля окна между первой и последней точками, по умолчанию 0.9 |
| `noise_floor` | Положительный нижний предел масштаба шума в нормализованных единицах |
| `huber_delta` | Коэффициент ограничения влияния остатков, по умолчанию 1.5 |
| `iterations` | Максимальное число итераций робастной регрессии, по умолчанию 12 |
| `step_ratio` | Отклонить тренд, если SSE двух уровней меньше этой доли SSE линии; 0 отключает проверку |
| `confirmation` | Число последовательных оценок с одним направлением для реакции |
| `max_samples` | Ограничение памяти; по умолчанию 4096 наблюдений |

Тангенс — **не процент изменения и не угол в градусах**. При CPU в диапазоне 0–100
рост 20 → 80 за 10 минут имеет tangent=6 при value_scale=1, либо 0.06 при
value_scale=100. Время отклика в миллисекундах при value_scale=1 даёт мс/мин.
Порог дисперсии меняется квадратично при изменении value_scale.

Дисперсия здесь не дисперсия всего ряда и не обычная несмещённая оценка:
это средний квадрат остатков, ограниченных по модулю `huber_delta * sigma`,
где sigma определяется через MAD. Реальный тренд не увеличивает её автоматически,
а одиночные большие выбросы не доминируют. Повышение variance_threshold
**разрешает более шумные ряды**, а не делает проверку строже.

`ready=False` означает прогрев/недостаточное покрытие. Другие reason:
`flat`, `variance`, `step`, `confirmation`, `trend`.
Срабатывание означает состояние тренда на данном окне; одно событие может дать
несколько срабатываний подряд. Объединение алертов делается вызывающим приложением.
Повторный evaluate без новых данных не продвигает confirmation.

Границы окна включены: при регулярном scrape 15 с двухминутное окно содержит
9 точек с обеими границами, десятиминутное — 41, получасовое — 121.
NaN/Inf, дубликаты и обратный порядок timestamp отклоняются до изменения состояния.
Нерегулярные timestamps допустимы; пропуски не интерполируются. Покрытие учитывает
размах timestamps, но не гарантирует равномерность наблюдений внутри окна.
Если max_samples слишком мал для полного окна, детектор останется в прогреве.

## Алгоритм и ограничения

1. Ограниченный буфер исходных точек, удаление данных за пределами окна.
2. Робастная начальная оценка по разнесённым парам и Huber IRLS.
3. Оценка остаточного шума через MAD и ограниченные остатки.
4. Сравнение линии с моделью двух уровней на одинаковых очищенных данных.
5. Проверка дисперсии, минимального наклона и подтверждения направления.

Проверка скачка — эвристика, не статистический тест или гарантия различения
скачка и тренда. Поиск разрыва использует префиксные суммы; края с менее чем
max(2, n//5) точками не рассматриваются. Детектор не моделирует периодичность:
короткая часть длинной GC-пилы может выглядеть как рост. Он оценивает локальный
наклон относительно горизонтали; изменение наклона относительно предыдущего
окна отдельным тестом в этой версии не реализовано.

Пороги не являются p-value, confidence interval или контролем частоты ложных
алертов. Восемь наблюдений не дают универсальной уверенности. Робастность к пикам
может скрывать рост именно пиков — для хвостовых задержек нужны отдельные метрики.
Накопительные counters сначала следует преобразовать в rate с обработкой reset.

Обновление буфера — амортизированное O(1); оценка — O(iterations * n * log(n))
из-за сортировки для медиан в Python, память — O(n). Это проверяемая эталонная
реализация, **не подтверждённая нагрузочным тестом на миллион рядов**.
Миллион Python-объектов и буферов требует существенно больше памяти, чем плотный
массив float64. Для этого масштаба нужны измерения, пакетная численная реализация
и/или предварительный отбор кандидатов с проверкой полноты обнаружения.

## Сценарии

Исходные данные генерируются в `tests/scenarios.py` с фиксированными seed,
scrape=15 секунд, проверка=60 секунд. Это синтетические fixtures, не интернет-данные.

| Ряд | Конфигурация/ожидание |
|---|---|
| Две наложенные GC-пилы без дрейфа | 30 минут: нет тревог |
| Те же пилы с дрейфом +1.5 единицы/мин | 30 минут: рост |
| CPU 20 → 80% за 10 минут с колебаниями | 10 минут: рост; слишком строгая дисперсия его подавляет |
| Низкошумный response time, +2 мс/мин | 2 минуты: обнаружение не позднее двух минут после начала |
| Одиночный всплеск, скачок, временная ступенька | 2 минуты: нет трендовых тревог |
| Backpressure: рост, затем падение | 2 минуты: обнаруживаются оба направления |
| Субмиллисекундные задержки с тяжёлым хвостом без дрейфа | Чувствительная конфигурация даёт ложные тревоги; порог наклона, дисперсия или длинное окно подавляют их на fixtures |

Есть дополнительные проверки единиц, нерегулярных timestamps, прогрева,
повторной оценки, подтверждения, неверных входов, границ памяти и пяти seed шума.
Эти тесты проверяют выбранные сценарии, а не доказывают отсутствие ложных тревог
на произвольной телеметрии.

## CUSUM: берсты и пила

`apps.detectors.CusumDetector` возвращает балл дефекта `[0, 1]` в текущем
скользящем окне относительно фонового шума. Произведение направлений сохраняет
чувствительность к просадкам с восстановлением и пиле; смену уровня и тренд
проверяют другие детекторы. API, прогрев, параметры и ограничения — в [CUSUM.md](CUSUM.md).

четырёх точных fixtures из `CUSUM_TEST.py`, а также показывает синтетические
пилу на спокойном/шумном фоне, смену уровня и горизонтальную прямую.

## Предиктивный интервал следующей точки

`apps.detectors.PredictionIntervalDetector(Detector)` строит границы по предыдущему
окну, возвращает `infimum`, `supremum` и балл `[0, 1)`. Поддерживает ручной масштаб,
калибровку на обучающем ряду и авторегуляцию по прошлым промахам.
При стабильных границах балл по умолчанию ослабляется в 10 раз;
`raw_score` сохраняет исходную оценку отклонения.
API, тесты и результаты: [PREDICTION_INTERVAL.md](PREDICTION_INTERVAL.md).


## Изменение связи между скоррелированными рядами

`apps.detectors.CorrelationDetector` учится онлайн из взаимодействия рядов;
выбирать нормальные участки и вызывать `fit` для запуска не требуется.
С пятой точки скор вычисляется непрерывно, включая период наполнения окна.
API, ограничения, полная временная шкала и тесты с чтением из InfluxDB —
[CORRELATION_CHANGE.md](CORRELATION_CHANGE.md).

Корреляционный скор учитывает относительное расхождение на текущем уровне
(`relative_change_scale=0.1`) и настраиваемый допуск времени сбора
(`alignment_tolerance=1` для ±1 отсчёта). Допуск добавляет задержку выдачи;
результат различает индекс оцениваемой точки и индекс выдачи. Подробности и
сравнение на исходных рядах — в [CORRELATION_CHANGE.md](CORRELATION_CHANGE.md).
