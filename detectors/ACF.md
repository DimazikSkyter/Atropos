# ACFDetector: изменение памяти временного ряда

Обновление от 11 ноября 2026: тесты и [HTML-отчёт](artifacts/acf/report.html#replay-inputs)
используют исправленный «Сценарий» из InfluxDB за 17–18 октября:
четыре TPS-ряда с сохранённой шириной пиков и откатов, а также Cassandra.

Реализация находится в `apps/detectors.py`. Детектор оценивает изменение связей
между значениями ряда на разных лагах относительно здорового фона.
Он принимает скалярные значения метрики или результатов другого детектора,
возвращает балл изменения лагового профиля и его глубину. Тип события,
его амплитуда и причинно-следственная связь не определяются.

Из **каждого окна вычитается его собственное среднее**. Если переход на новый
уровень вышел из окна, новый уровень становится нормой. Например, при окне
40 точек и шаге 15 секунд переход забывается не позднее заполнения окна
за 10 минут. Предыдущее среднее не удерживается. Сам шаг в API не передается:
единицы лага задает вызывающий код.

Фиксированный фон нужен для сравнения **формы ACF**, а не уровней или дисперсий.
Обычная автокорреляция сглаженного входа не должна сама вызывать тревогу.
Если изменилась именно структура зависимостей, отличие от фона может сохраняться
и после заполнения окна. Принятие такой структуры за новую норму делается через
новый `fit(healthy_history)`.

## Использование

```python
from apps.detectors import ACFDetector

# 10 минут локальной истории при шаге 15 секунд.
# Дальнейший горизонт проверки — 10 лагов, то есть 150 секунд.
detector = ACFDetector(
    window=40,
    max_lag=10,
    reference_window=160,
).fit(healthy_values)

for value in lower_level_detector_scores:
    score = detector.update(value)
    if detector.ready:
        result = detector.result
        print(score, result.depth, result.significant_lags)
        print(result.depth * 15)  # глубина в секундах

# Независимый пакетный прогон; активный поток не меняется.
scores = detector.detect_single_seria(values)
last_score = detector.detect(values)  # score(values) — синоним
last_result = detector.analyze(values)
```

Один экземпляр хранит состояние одного ряда; экземпляр не потокобезопасен.
Равномерность входного шага обеспечивает вызывающий код. NaN, Inf, bool,
строки и нечисловые значения отклоняются до изменения состояния.

`fit()` требует не менее `window` здоровых значений и сохраняет не более
`reference_window` последних. После него требуется **отдельное полное локальное
окно**. Последняя точка фона не соединяется с первой точкой нового потока.

Без `fit()` первые `reference_window` точек принимаются за здоровый фон;
следующие `window` точек заполняют локальное окно. По умолчанию первый готовый
результат появляется на 768-й точке, после явного `fit()` — на 256-й.
До готовности балл равен 0, `ready=False`; измеренный ноль имеет `ready=True`.
`reference_ready` отдельно показывает готовность фонового профиля.

Фон после прогрева не обновляется аномальными окнами. `reset()` очищает поток,
сохраняя только фон, явно заданный через `fit()`; автоматически изученный фон
обучается заново. Повторный `fit()` заменяет фон и сбрасывает поток.
Невалидный `fit()` сохраняет предыдущее состояние.

## Параметры

| Параметр | По умолчанию | Смысл |
| --- | ---: | --- |
| `window` | 256 | Число точек текущего окна, минимум 8 |
| `max_lag` | 32 | Проверяются лаги 1…max_lag; `4 * max_lag <= window` |
| `reference_window` | 512 | Максимальная длина фона; не меньше `window` |
| `threshold` | 3.5 | Положительный множитель приближенного шумового порога |
| `min_change` | 0.1 | Минимальное изменение коэффициента ACF, диапазон [0, 2) |
| `logger_name`, `logger_props` | Как у `Detector` | Логгер |

Большие окна дают более устойчивые оценки, но дольше сохраняют старый переход.
На шаге 15 секунд окно по умолчанию занимает 64 минуты, горизонт — 8 минут.
Окно 40 точек в примере занимает 10 минут и имеет меньшую чувствительность.
Слишком большой порог при коротком окне может подавить все изменения.
Параметры остаются в точках, привязки к минутам в реализации нет.

## Расчет

Для каждого окна отдельно:

```text
z[t] = x[t] - mean(x)
rho[k] = sum(z[t]*z[t+k], t=0..N-k-1) / sum(z[t]**2, t=0..N-1)
```

Это обычный biased sample ACF с общим знаменателем лаговой энергии;
коррекция на `N-k` не применяется. Лаг 0 не участвует в балле.
Нормировка масштабированием и сдвигом до суммирования защищает вычисления
от переполнения на противоположных значениях порядка 1e308, потери малых
колебаний на большом уровне и обнуления квадратов на значениях порядка 1e-320.
Постоянный ряд имеет нулевую энергию: статистически ACF не определен.
Для рабочего API возвращается нулевой профиль с явным флагом `zero_energy`.

Пусть `N` — длина локального окна, `M` — фактическое число фоновых точек,
`r[k]` — здоровый ACF:

```text
noise[k] = sqrt((1 + 2 * sum(r[j]**2, j=1..k-1)) * (1/N + 1/M))
band[k] = min(2, max(min_change, threshold * noise[k]))
change[k] = abs(rho[k] - r[k])
excess[k] = min(1, max(0, change[k] - band[k]))
significant_lags = лаги k, где change[k] > band[k]
depth = max(significant_lags), либо 0
lag_mass = sum(excess[k], k=1..max_lag)
score = lag_mass / max_lag
```

Порог использует здоровый ACF и учитывает погрешность обоих окон по мотивам
приближения Бартлетта. Текущее аномальное окно не увеличивает собственный порог.
Это инженерная эвристика: полоса не является точным доверительным интервалом,
`threshold` не задает p-value, последовательные скользящие окна зависимы.
Нулевая энергия и нестационарные переходы дополнительно выходят за обычные
предпосылки статистической интерпретации ACF.

Используется **модуль разности подписанных ACF**: учитываются и появление,
и исчезновение памяти, отрицательная связь и отложенная связь без лага 1.
Балл 0…1 отражает среднюю превышающую порог массу по выбранным лагам;
это не вероятность и не бинарный вердикт. Порог алерта задает вызывающий код.

`result` — неизменяемый `ACFResult` с полями `ready`, `score`, `depth`,
`lag_mass`, `horizon_reached`, `acf`, `reference_acf`, `lag_changes`,
`thresholds`, `significant_lags`, `zero_energy`, `reference_zero_energy`.
Массивы включают лаг 0 и представлены кортежами. До готовности массивы пусты.

`depth` — **последний значимый лаг**, не время начала события, не возраст
инцидента и не точная длительность восстановления. Отдельный слабый дальний
лаг может увеличить depth при почти нулевом score; читать их нужно вместе.
`horizon_reached=True` означает значимое изменение на `max_lag`, поэтому
проверенного горизонта недостаточно, чтобы установить более дальнюю границу.

### Изменение цикличности по примеру пользователя

Синтетические сценарии воспроизводят регулярные циклы, переходящие к другой
частоте или нерегулярному периоду. Смешанный случай также увеличивает амплитуду,
как на присланном изображении. Числовые периоды и время — параметры fixtures;
для изображения исходные отсчеты не предоставлялись.

Начальный период — 16 точек. Изменение действует с точки 450 по 1049,
после него прежний период восстанавливается. Фаза непрерывна, шума немного,
здоровый фон содержит исходный цикл. Локальное окно 256, max_lag=32,
фон 512; алгоритм и пороги не менялись.

| Сценарий | Пиковый score, seed=43 | Depth при пиковом score |
| --- | ---: | ---: |
| Период 16 → 32 → 16 | 0.17529 | 18 |
| Период 16 → 8 → 16 | 0.17135 | 25 |
| Нерегулярные периоды 8, 12, 28, 40 | 0.09224 | 18 |
| Постепенное изменение периода и рост амплитуды | 0.15649 | 26 |
| Только амплитуда ×3.5, прежняя структура цикла | 0 | 0 |

На трех seed средние баллы после заполнения окна измененными циклами:
0.1722–0.1725 при периоде 32; 0.1703–0.1706 при периоде 8;
0.0587–0.0974 при нерегулярных циклах; 0.1035–0.1040 в смешанном сценарии.
До изменений и после полного окна восстановления баллы нулевые на всех трех seed.
Контроль с ростом только амплитуды масштабирует сигнал вместе с шумом,
сохраняя их отношение, и не дает реакции на всем прогоне.

При чистом удвоении периода лаг 16 меняет смысл: прежний цикл повторяется,
а новый находится в противофазе. Отдельный тест проверяет переход
`reference_acf[16] > 0.9` к `acf[16] < -0.9` и значимость этого лага.
Отличие от фиксированного фона сохраняется и в окне, полностью занятом
новыми циклами: смена структуры зависимости обнаруживается до ее восстановления
либо нового `fit()`.

### Шум и производительность

На 1000 независимых локальных окнах белого шума (40 фоновых seed × 25 окон)
ненулевой балл получили **6 окон, 0.6%**; максимальный score=0.000735.
Это результат конкретного эксперимента, не гарантия для реальной телеметрии.
На контрольной смене только разброса возник слабый score=0.01261.
У короткого восстановления отдельные слабые дальние лаги давали depth=20,
хотя depth на максимуме балла равен 2. Эти результаты показывают, почему
нельзя использовать один depth как самостоятельную тяжесть события.

Замер 1000 последовательных готовых обновлений при N=256, max_lag=32:
медиана около 0.82 мс, p95 около 1.24 мс на данной машине, Python 3.12.0.
Точные показатели конкретного запуска записаны в `summary.json`.
Время одного обновления O(N × max_lag), память O(M + N + max_lag).
Новых зависимостей для рабочего детектора нет; NumPy, statsmodels и Matplotlib
используются существующим окружением для тестов и отчета.

## Ограничения

- ACF описывает линейные временные связи. Он не доказывает причинность
  и не различает тренд, цикл и инерционное восстановление по типу события.
- Сдвиг и масштаб всего ряда не меняют ACF. При изменении амплитуды только
  события на неизменном шумовом фоне меняется отношение сигнал/шум,
  поэтому обнаружимость также может меняться.
- Сглаживание, перекрывающиеся окна и внутреннее состояние нижестоящего
  детектора сами создают память. Обучать фон нужно на его здоровом выходе.
- На коротком окне оценки менее устойчивы; более дальние лаги за max_lag
  не проверяются. Подбор окна и порогов требуется проверить на реальных данных.
- Постоянные ненулевые значения сами по себе не означают память:
  после вычитания среднего энергия равна нулю, и переход считается завершенным.

Определение ACF и требование равномерных наблюдений:
[NIST](https://www.itl.nist.gov/div898/handbook/eda/section3/eda35c.htm).
Нормировка biased ACF и приближенные ошибки:
[statsmodels](https://www.statsmodels.org/stable/generated/statsmodels.tsa.stattools.acf.html).
Сравнение двух профилей, итоговый score и depth — определения этой реализации.
