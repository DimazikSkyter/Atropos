# Обновление 22 ноября 2026: рост CPU на фоне провалов

Основной режим `evidence_mode='regression'` оценивает изменение наклона и
смещение относительно погрешностей двух регрессионных линий. Используется
HAC-оценка с весами Бартлетта для учёта корреляции остаточного шума.
Нормировка только на разброс одиночных точек (`evidence_mode='residual'`)
на CPU подавляла накопление до нуля, хотя устойчивый рост уже был виден.
Предыдущая нормировка доступна для сравнения. `_fresh()` сохраняет режим.

Прогрев, ограниченная память, причинность и проверка излома сохранены. Ненулевая
реакция до подтверждения означает предварительное свидетельство, а не сигнал
`detected=True`. Полный трёхчасовой CPU с шагом 15 секунд включён в проверку:
ранние циклы дают низкий отклик, а рост в конце — заметный. Будущие точки не
меняют оценки в уже обработанном префиксе.

Погрешности вычисляются только на двух текущих окнах; объём истории не растёт.
Для каждого готового наблюдения стоимость HAC — O(W sqrt(W)); массивы O(W),
где W=data_max_size. Это дополнительная стоимость относительно прежних O(1)
скользящих моментов. FFT и спектральная модель не используются.

Сравнение на точных сохранённых данных: [CPU: до и после](artifacts/cpu-detectors/report.html).

# TrendDetector: смена тренда и её начало

Реализация: `apps/detectors.py`. Отчёт: [artifacts/trend-change/report.html](artifacts/trend-change/report.html).
Детектор причинный: каждое решение использует только поступившие наблюдения.
`RuntimeTrendDetector` и его отчёт сохраняют свой прежний API и назначение.

```python
from apps.detectors import TrendDetector

detector = TrendDetector(window=40, data_max_size=240)
for value in values:  # равномерный шаг
    result = detector.update(value)
    if result.ready:
        print(result.score, result.horizontal)
    if result.detected:
        print(result.change_start, result.confirmed_at, result.direction)
```

`result.score` находится в [0, 1]. `result.horizontal` — bool после прогрева,
до него `None`. `detected` требует score ≥ 0.8 и проверки формы излома.
Значение 1 означает, что короткая память заполнена сильными подтверждениями.
Score — сила подтверждения, не калиброванная вероятность аномалии.

## Два окна и короткая память

Большое окно `data_max_size=240` включает две непересекающиеся части:
предыдущие 200 наблюдений и концевые `window=40` наблюдений.
Опорная линейная регрессия оценивает прежнее поведение. Концевая измеряет
новый наклон и смещение от продолжения опорной линии.
Остаточный масштаб каждой линии равен `sqrt(SSE/(n-2))`.

```
sigma = max(reference_residual_RMS, tail_residual_RMS, noise_floor)
strength = min(abs(b_tail-b_ref)*(window-1), abs(displacement)) / sigma / threshold
evidence = clip(strength-1, 0, 1)
```

Evidence допускается только при согласованных знаках изменения наклона и
смещения. Score — среднее evidence короткой памяти одного направления.
По умолчанию её длина `max(3, window//3) = 13`. Противоположное направление
очищает память; отсутствие evidence постепенно вытесняет накопленную реакцию.
Одиночный сильный отсчёт не может заполнить память.

При достаточном накоплении проверяется непрерывный излом
`y=a+b*x+delta*max(0,x-k)` по всем допустимым k большого окна:

- SSE излома должна быть не больше половины SSE одной линии;
- не больше 1.3 SSE двух независимых линий — защита от скачка уровня;
- не больше 0.8 SSE кубического полинома — защита от гладкой волны;
- изменение наклона должно превышать остаточный шум и совпадать с направлением evidence.

До успешной проверки score ограничен 0.79. Оценённое начало фиксируется при
первом подтверждении. Новый устойчивый режим затем попадает в опорное окно,
и score снижается: это детектор **смены**, а не постоянный индикатор роста.
Смена роста на плато также считается сменой наклона.

## Когда смена началась

`change_start` — оценённый нулевой индекс излома; `confirmed_at` — индекс,
когда эта оценка стала доступна онлайн. До подтверждения оба поля `None`.
Точка k лежит на пересечении старой и новой прямых и считается началом.
Излом между отсчётами допускается; возвращается ближайший целый индекс.
Поля сохраняются на протяжении активного эпизода, после затухания очищаются.
Для хранения истории приложение сохраняет результат первого подтверждения.
Ключ эпизода — `confirmed_at`, а не каждый отсчёт `detected=True`.

`direction` обозначает изменение наклона: +1 — наклон увеличился,
−1 — уменьшился. Поэтому замедление роста имеет direction=-1, хотя сам
`slope` может оставаться положительным. Направление до подтверждения может
показывать предварительное evidence; оно не является отдельной тревогой.

Точность локализации и задержка подтверждения — разные метрики.
Нельзя использовать оценку начала как сигнал, будто он был доступен в прошлом.
В отчёте обе метрики считаются отдельно, а пропущенные смены остаются в recall.

## Горизонтальность и единицы

```
slope = (изменение value / value_scale) * time_scale / sample_interval
angle = degrees(atan(slope))
horizontal = abs(angle) <= angle_tolerance  # по умолчанию 1°
```

По умолчанию все масштабы равны 1: единица значения за один отсчёт.
Угол зависит от осей; он не является универсальным свойством ряда.
Например, при шаге 15 секунд и метрике в миллисекундах:

```python
detector = TrendDetector(sample_interval=15, time_scale=60, value_scale=1)
# slope в мс/мин; horizontal означает |slope| <= tan(1°) мс/мин.
```

Горизонтальность относится к оценённой линии концевого окна. Её можно
получить и при продолжающемся подтверждении перехода к плато.
Неравномерный поток следует сначала привести к регулярному шагу.

## API и параметры

| Параметр | Значение по умолчанию | Смысл |
|---|---:|---|
| `window` | 40 | Число концевых точек, минимум 6 |
| `data_max_size` | 240 | Полное окно, не меньше 3×window |
| `inertia_window` | 13 | Короткая память, 2…window |
| `threshold` | 2 | Требуемый размер эффекта относительно RMS |
| `noise_floor` | 1e-9 | Нижний предел RMS в нормализованных единицах |
| `value_scale` | 1 | Масштаб оси значений |
| `sample_interval` | 1 | Интервал наблюдений |
| `time_scale` | 1 | Единица времени для slope |
| `angle_tolerance` | 1 | Предел горизонтальности в градусах |

`update(value) -> TrendResult`; `result` — последний результат;
`ready` — прогреты ли окна; `reset()` очищает поток.
`detect(data)` возвращает последний TrendResult независимого повтора.
`score(data)` возвращает последний float; `detect_single_seria(data)` —
список float для совместимости с графическим API других детекторов.
Пакетные методы не меняют активное состояние экземпляра.
Пустой ряд возвращает непрогретый результат. NaN/Inf/bool отклоняются
без продвижения состояния. Непредставимые масштабированные значения также
отклоняются; модуль центрированного значения ограничен 1e100.

## Стоимость и ограничения

OLS-моменты обновляются за O(1) амортизированно. Периодический пересчёт с
локальным началом координат ограничивает накопление ошибок округления.
Поиск излома стоит O(W) и выполняется для нового кандидата не чаще одного
раза за I отсчётов. Итого O(1+W/I) амортизированно, O(W) в худшем обновлении;
память O(W+I), независимо от длины истории. FFT и итерационных оптимизаторов нет.

Полностью отличить длинный кусок цикла от настоящего кусочного тренда
при ограниченном окне невозможно. Длинная треугольная волна содержит те же
локальные изломы, что и настоящий тренд. Большое окно должно видеть
характерные циклы; в тестах отдельно сравниваются короткий и достаточный контекст.
Шум с сильной памятью и случайное блуждание также могут давать ложные события.
Плавный излом, близкие смены, ступенчатый рост и смена до прогрева показаны
как сложные случаи. Слабые изменения на сильном шуме могут пропускаться.

Увеличение концевого окна улучшает чувствительность к слабому наклону на шуме
ценой задержки. Отчёт сравнивает 20/120, 40/240, 60/360 и несколько threshold
на одинаковых рядах. Метрики прежних детекторов не используются как эталон.

## Воспроизведение

Отчёт от 3 ноября 2026 включает **1101 ряд и 907 964 отсчёта**: 82 основных
сценария, 59 прежних fixtures и 960 Monte Carlo рядов на 40 seed.

| Группа | Найдено смен | MAE начала, отсчёты | Медиана задержки, отсчёты |
|---|---:|---:|---:|
| Основные изломы с разным шумом | 23/24 | 0.39 | 35 |
| Четыре последовательных излома | 4/4 | 0 | 35 |
| Смена на фоне циклов | 3/3 | 4.67 | 46 |

В Monte Carlo обнаружено 402/640 смен: слабые эффекты на сильном шуме
часто пропускаются. Например, Δslope=0.1 при σ=1 — 0/80, тогда как
Δslope=0.3 при σ=1 — 80/80. Ошибки начала считаются только для обнаруженных
смен, поэтому таблица ошибок должна читаться вместе с recall.

На белом шуме, цикле P=60, гладком цикле P=600, ступеньке и AR(0.9)
ложных событий в Monte Carlo нет. На случайном блуждании они есть в 8/40
рядов, AR(0.98) — 4/40, длинном треугольном цикле P=600 — 40/40.
Последний случай показывает необходимость окна, покрывающего цикл;
тест с большим окном 1200 подавляет этот контроль.

Полный прогон: 246 тестов, 245 успешны, один live-интеграционный тест
VictoriaMetrics пропущен без `RUN_VM_INTEGRATION=1`. Измеренная скорость
при 40/240 — около 97 тыс. обновлений/с на стационарном сигнале и 78 тыс.
на кусочном. В отчёте указаны машина, повторы и методика измерения.
