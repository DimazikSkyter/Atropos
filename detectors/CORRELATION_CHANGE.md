# Изменение связи: относительный размер и рассинхронизация сбора

`CorrelationDetector` учится из взаимодействия рядов без ручной разметки
нормальных участков. Текущая CCF сравнивается с медленной оценкой связи,
а тяжесть нарушения учитывает **относительное расхождение на текущем уровне**.

```python
from apps.detectors import CorrelationDetector

detector = CorrelationDetector(
    window=12, max_lag=2, reference_window=64,
    alignment_tolerance=1,      # допустимый сдвиг времени сбора: ±1 отсчёт
    relative_change_scale=0.1, # расхождение 10% даёт относительный вес 0.5
)
for row in incoming_rows:       # [metric1_t, metric2_t, ...]
    result = detector.update(row)
    if result.ready:
        save_score(result.score_index, result.score,
                   issued_at_index=result.observed_index)
```

Колонки имеют неизменный порядок, точки выровнены на равномерной временной
сетке. `alignment_tolerance` выражен в **отсчётах**, не секундах.

## Относительный размер расхождения

При прочих равных `15/400 = 3.75%` должно влиять сильнее, чем
`25/800 = 3.125%`. Абсолютный разрыв в 25 единиц на высоком уровне
не должен автоматически давать больший балл.

По ранее принятым взаимодействиям каждая установленная пара обучает аффинную
зависимость в обе стороны. Она учитывает обычное смещение и масштаб пары.
На согласованном окне вычисляются:

```text
expected_y = mean_y + r * ((x - mean_x) / std_x) * std_y
expected_x = mean_x + r * ((y - mean_y) / std_y) * std_x
error_y = abs(y - expected_y) / max(abs(expected_y), reference_std_y)
error_x = abs(x - expected_x) / max(abs(expected_x), reference_std_x)
e = RMS(error_x, error_y)  # по обоим направлениям и всем точкам окна
relative_weight = e / (e + relative_change_scale)
```

Уровень в знаменателе — **ожидаемый текущий уровень**, не средний уровень
всего графика и не размер его шума. `reference_std` служит защитой около
нуля, где проценты от уровня не определены. Ошибки насыщаются на 200%,
чтобы противоположные знаки и экстремальные конечные числа не ломали арифметику.
Взаимная нормировка сохраняет результат при смене единиц каждой метрики.
Добавление большой постоянной к уровням намеренно меняет относительный вес.

`relative_change_scale` по умолчанию **0.1**. При e=0.1 вес равен 0.5;
чем больше параметр, тем слабее влияние небольших относительных расхождений.
Значение **0** отключает этот вес для сравнения с чистой корреляцией.
Нормальное постоянное смещение пары уже включено в прогноз и не является
новым нарушением.

Итоговый балл пары — балл изменения корреляции, умноженный на относительный
вес. Уровень отдельного ряда сам по себе не формирует тревогу. Полностью
сохранившаяся корреляция после смены уровня может давать нулевой балл даже
при большой относительной ошибке; для самостоятельного контроля уровня
требуется отдельный критерий.

## Допуск времени сбора

`alignment_tolerance=0` — строгое сопоставление по установленному лагу
(значение по умолчанию для совместимости). При **1** для каждой выдаваемой
оценки проверяются сдвиги −1, 0, +1 относительно этого лага.
Выбирается наиболее согласованное сопоставление окна.

Внутри одного окна используется один сдвиг. Произвольный независимый подбор
каждого значения мог бы искусственно скоррелировать случайные ряды.
Сдвиг может меняться при следующем обновлении. За пределы заданного допуска
поиск не выходит, поэтому устойчивый больший сдвиг не подстраивается автоматически.

Для правого соседа нужен буфер: скор точки t выдаётся после прихода t+radius.
`CorrelationResult` различает:

| Поле | Значение |
|---|---|
| `score_index` | индекс оцениваемой точки |
| `observed_index` | индекс входа, при котором скор выдан |
| `alignment_delay` | задержка выдачи в отсчётах |
| `ready` | доступна оценка для указанной точки |
| `pending` | результата для точки пока нет из-за ожидания соседа |
| `provisional` | короткое окно ещё растёт |

`replay` возвращает один **выданный результат** на каждый вход,
а не делает вид, что задержки нет. В отчёте `align_results` раскладывает
результаты по `score_index`; CSV сохраняет и `timestamp`, и `issued_at`.
Последняя точка конечного файла остаётся `pending=True`: будущий сосед
не выдумывается. В бесконечном потоке очередной вход закрывает эту оценку.

Правая окрестность используется только для задержанного сопоставления.
Обучение CCF, модели уровня и gate использует строгие данные до оцениваемой
точки включительно. Точка сначала оценивается, затем обучает следующие
оценки. Правый сосед не попадает в собственный эталон через lookahead.

Ограничения: радиус — целый >=0, не больше `window//4` и `min_samples-3`.
При увеличении радиуса надо обеспечить достаточно стартовых точек.
Режим `adaptive=False` требует нулевого радиуса.

## Установление связи и общий скор

Пары устанавливают подписанный лаг при `abs(r) >= min_correlation=0.7`.
Связь должна подтвердиться с одинаковым знаком в двух непересекающихся
частях окна и распределяться между несколькими приращениями. Одиночного
доминирующего скачка и случайной корреляции первых четырёх точек недостаточно.
Для подтверждения используется минимум `min(window, 2*min_samples)` точек.
До первого полного окна могут устанавливаться только нулевые лаги;
ненулевые требуют полного окна.

Скор доступен с `min_samples=5`, даже пока подтверждение пары продолжается.
`pair.monitored=False` и число `monitored_pairs=0` явно показывают отсутствие
подтверждённого эталона. Нулевой скор тогда не подтверждает исправность.

```text
distance = clip((abs(r_current-r_reference) - min_change)/(1-min_change),0,1)
correlation_score = distance * activity_weight
pair_score = correlation_score * relative_weight
raw_score = max(pair_score)
score = moving_mean(raw_score, persistence)
detected = score >= alert_threshold
```

В прогонах одинаковы `min_change=0.25`, `alert_threshold=0.4`,
`relative_change_scale=0.1`, `alignment_tolerance=1`, `persistence=2`.
По умолчанию persistence=3. Это эвристический скор, не вероятность.

На плоских участках используется порог информативности
`max(noise_floor, relative_noise_floor * prior_std)`, по умолчанию
абсолютная часть 0, относительная 0.3. Вес растёт от 0 на этом пороге до 1
при тройном пороге. Остановка одного участника означает потерю установленной
связи; два неинформативных участка не несут доказательств нарушения.

Медленный эталон обновляется с `alpha=max(2/(reference_window+1),1/startup_count)`.
Обновление уже установленной пары требует информативной, достаточно сильной
строгой корреляции того же знака и невысокой корреляционной тяжести.
Сильное нарушение не обучает собственный эталон.

В `CorrelationPairResult` отдельно доступны `raw_correlation`,
`aligned_correlation`, `alignment_shift`, `relative_error`, `relative_weight`,
`correlation_score` и итоговый `score`. Сырые CCF и предыдущий эталон также
сохранены; значения с недостаточной дисперсией не выдаются за точную корреляцию.

вес, чтобы изолировать математические контракты. Отдельная suite проверяет
правило 15/400 > 25/800, нормальный offset/gain, смену единиц, близость к нулю
и сохранение реакции на крупное расхождение. Live-suite проверяет обе поправки вместе.

## Ограничения

Это реконструкция изображений с 3+4 различимыми линиями и интерполяцией
перекрытий, а не исходная телеметрия с метками аварий. Результаты не являются
precision/recall. Онлайн-обучение устанавливает согласованность, не истинную
нормальность; начальное нарушение может стать первой связью. Очень медленные
изменения могут усваиваться эталоном. Окно и радиус влияют на задержку и
различимость; более крупная временная рассинхронизация требует явного допуска.

`fit` остаётся необязательной прошлой историей. `reset` очищает активный поток
и восстанавливает только явный fit. Batch-методы не меняют активный поток.
Память ограничена окнами, буфером радиуса и числом пар;
обновление O(число_пар × (число_лагов+radius) × window).
`adaptive=False` сохраняет прежний замороженный алгоритм без этих адаптивных
весов. Другие детекторы и ACF/PACF-анализатор не меняются.
